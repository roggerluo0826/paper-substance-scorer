# 讀者對位 (Audience Fit)

> **分數是論文的屬性。有用與否是「讀者 × 論文」的關係。**
> 打分器只給前者,會產出「分數很高、讀者讀完說沒用」的推薦。

這份文件補的是切題度與嚴謹度**兩軸都測不到**的那個東西。

---

## 為什麼需要第三個問題

| | 切題度 | 嚴謹度 | **讀者對位** |
|---|---|---|---|
| 問 | 這篇夠不夠切題? | 這篇可不可信? | **這篇是寫給誰的?** |
| 怎麼算 | 關鍵字加權 | 7 維度讀全文 | 看動機句與結論訴求對象 |
| 是誰的屬性 | 論文的 | 論文的 | **讀者與論文的關係** |

前兩軸都是論文自己的屬性,跟誰在讀無關。**第三軸是關係,換一個讀者就換一個答案。**

---

## 完整失敗案例:DeepMind BCOOLER

**論文**:Luo et al., *Controlling Commercial Cooling Systems Using Reinforcement Learning*, arXiv 2211.07357 (DeepMind + Google + Trane Technologies, 2022)

**讀者**:ESCO 節能顧問(獨立作業,做冰機診斷與績效保證,不寫 RL)

### 兩軸都給了綠燈

| 軸 | 評 |
|---|---|
| 切題度 | **滿分**。HVAC + RL + 真實部署 + 冰機群控,關鍵字全中 |
| 嚴謹度 | **81 分 B+**。兩個真實設施各 3 個月 A/B;對照組是 Trane 真實 SOO 而非稻草人;**還先把 baseline 調校過再比**;有專節誠實列 6 個挑戰 |

### 讀者實際反應

> 「這篇我看完了,對我沒有用處。第一點強化學習不是我的厲害範圍,第二點裡頭結論我看不出哪想表達什麼。」

**讀者是對的。**

### 診斷:動機句就寫在摘要裡

> "Our paper describes these challenges **in the hope that awareness of them will benefit future applied RL work**."

**預期讀者 = 想做應用 RL 的工程師。** 不是 HVAC 顧問。

結論那句「we found that no off-the-shelf RL algorithm can work in a plug-and-play fashion」:
- **對 RL 工程師** → 重要警告,值回票價
- **對 ESCO 顧問** → 「……所以呢?」

**這篇對這位讀者沒有結論,因為它從來沒打算給他結論。**

### 但它有一頁是金子

**第 5.1 節的 A/B 協議**——一個**不需要基準線模型**的 M&V 方法:

```
① 每天交替:新舊控制器輪流控制整廠 → 兩者看到的天氣幾乎一樣
② 交接後 2 小時的資料丟掉 → 避免殘留效應
③ 外氣溫度和負載各切成「桶」,只比對落在同一桶的小時
④ 按各桶時數加權平均
```

**正確的推薦措辭不是「這篇值得讀」,是:**

> 「只讀 5.1 節那一頁。它給你一個不用建基準線模型的 M&V 協議。其餘的 RL 演算法細節(BCOOLER 的 BVE 約束最佳化)跳過。
> 適用邊界:只能用在**控制型**措施(可以今天新策略、明天舊策略);**設備型**措施(換主機)不能交替,還是得建基準線。」

### 而它真正的價值是負面情報

> DeepMind——36 個作者、Google 的資源、跟 Trane 合作、搞了一年——結論是「現成 RL 沒一個能隨插即用」,得靠階層式啟發式政策、動作剪枝、模式化動作遮罩硬撐,最後省 9%。

**對一個單人顧問,這是「別走 RL 這條路」的一級證據。**

比它的 9%/13% 值錢得多,而且**兩個分數軸都抓不到它**。

## 怎麼判斷預期讀者

**看這三個地方,通常在摘要和結論:**

1. **動機句** — `"in the hope that…"` / `"we hope this benefits…"` / `"this will be useful for…"` / `"for practitioners in…"`。作者自己會說。
2. **結論在訴求誰** — 結論那句話,如果換成一個外行來讀會說「所以呢?」,那讀者就不是他。
3. **作者社群** — 掛 DeepMind/Meta AI = 寫給 ML 社群;掛設備商/國家實驗室 = 比較可能寫給工程師;掛大學土木/機械系 = 寫給該領域。

**作者社群 ≠ 讀者社群時,要明講。** 一篇 DeepMind 寫的 HVAC 論文,是 **ML 論文**,不是 HVAC 論文——它只是拿 HVAC 當題材。

---

## 怎麼挖負面情報

主動問這四題:

1. **這篇有沒有證明什麼行不通?** — 「我們試了 X,失敗了」「現成的 Y 沒一個能用」
2. **它的「困難」章節在講什麼?** — Challenges / Lessons learned / Future work 常常比 Results 誠實
3. **它需要多少資源才做到?** — 36 個作者一年才 9%,那對一個人的意義是什麼?
4. **它的緩解措施是不是自曝?** — 「我們加了啟發式規則來救」= 承認主方法不夠

**負面情報常常是一篇論文對非目標讀者的唯一價值。** 別漏掉。

## 輸出模板

```
讀者對位
├─ 預期讀者:____(引用動機句佐證)
├─ 你是不是這個讀者:是 / 否 / 部分
├─ 能拿走的:第 __ 節,共 __ 頁。理由:____
├─ 可以跳過:____
├─ 適用邊界:____(這招在什麼情況下失效)
└─ 負面情報:____(它證明了什麼不該做)
```

## 給打分器自己的提醒

**這個 skill 最容易犯的錯,是看到「真實部署 + 漂亮方法論」就興奮,把嚴謹度分數當成推薦理由。**

81 分代表「這篇論文很紮實」。**它不代表「你該讀」。**

先問「這篇的結論在訴求誰」,再決定要不要推。**推的時候給頁碼,不要給整篇。**
