# 嚴謹度評分細則 (Rigor Rubric)

7 個維度加權,總分 0–100。每個維度先給該維度的 0–10 原始分,再乘權重。**每個分數都必須引用論文原文或數字當證據。**

## 維度與權重

| # | 維度 | 權重 | 問的核心問題 |
|---|---|---|---|
| 1 | 真實數據驗證 + 深度 | 20% | 有沒有拿真實數據/標準答案驗證?驗得夠不夠深(分項 vs 只看整體)? |
| 2 | 基準比較公平性 | 15% | 有沒有跟現有最佳方法公平比?對照組是不是稻草人? |
| 3 | 數字內部自洽 | 10% | 隨手挑幾組相關數字反推,兜不兜得起來? |
| 4 | 假設合理 + 可重現 | 15% | 假設貼近現實嗎?有沒有給足細節/程式/數據能重做? |
| 5 | 宣稱不超出證據 | 15% | 結論剛好等於數據能撐的範圍,還是過度外推? |
| 6 | Limitations 誠實度 | 15% | 敢不敢自曝缺點?講得具體還是打太極? |
| 7 | 不確定性量化 | 10% | 有誤差棒/信賴區間/敏感度/蒙地卡羅嗎? |

## 各維度 0–10 評分錨點

**1. 真實數據驗證 + 深度**
- 9–10:大規模真實數據 + 公認標準(如 ASHRAE Guideline 14)+ 分項驗證(逐子系統),甚至主動提高門檻。
- 6–8:有真實數據驗證,但只看整體 aggregate,或門檻寬鬆。
- 3–5:只用模擬對模擬,或驗證樣本很小。
- 0–2:幾乎沒有驗證,或用循環論證(拿模型驗自己)。

**2. 基準比較公平性**
- 9–10:跟現有 SOTA / 真實運轉數據公平比,條件對等。
- 6–8:有 baseline,但條件略偏心或版本較舊。
- 3–5:baseline 明顯偏弱。
- 0–2:對照組是稻草人(跟「什麼都不做」比),或根本沒 baseline。

**3. 數字內部自洽**
- 9–10:多組相關數字互相反推都吻合(如 ΔT 比 = Q/f 比)。
- 6–8:大致兜得起來,個別小出入。
- 3–5:有對不上或單位可疑之處。
- 0–2:明顯前後矛盾。

**4. 假設合理 + 可重現**
- 9–10:假設實在 + 程式/數據已公開,可完整重現。
- 6–8:假設實在,但程式/數據未公開(承諾接受後公開)。
- 3–5:關鍵假設偏理想化,或方法含糊難重做。
- 0–2:假設脫離現實,或完全無法重現。

**5. 宣稱不超出證據**
- 9–10:誠實區分「理論上限 vs 實務可行」,措辭精準("在這些條件下")。
- 6–8:大致克制,偶有小幅外推。
- 3–5:小樣本/單案例硬推普遍適用,或模擬講得像實測。
- 0–2:結論嚴重超出數據支撐。

**6. Limitations 誠實度**
- 9–10:專節列出多個具體技術缺陷,甚至自曝核心弱點。
- 6–8:有 Limitations,但偏籠統。
- 3–5:一兩句帶過。
- 0–2:完全沒有(大警訊)。

**7. 不確定性量化**
- 9–10:信賴區間 + 敏感度 + 蒙地卡羅/bootstrap,誤差有傳遞。
- 6–8:有敏感度分析,但無信賴區間。
- 3–5:只有點估計,零不確定性分析。
- 0–2:連基本變異都不提,還宣稱精確。

## 分數換算與等級

總分 = Σ(維度 0–10 分 ÷ 10 × 權重 × 100)

| 分數 | 等級 | 白話 |
|---|---|---|
| 85–100 | A 扎實 | 方法與結論都可信,可放心引用(注意 preprint 仍需標註) |
| 70–84 | B 有料有邊界 | 值得讀,但有明確該打折的地方,引用要小心措辭 |
| 55–69 | C 參考級 | 有想法但證據力不足,只能當 idea 參考 |
| 40–54 | D 存疑 | 多處不嚴謹,引用風險高 |
| < 40 | E 不建議 | 驗證/baseline 根本性缺失 |

> 注意:紅旗硬上限會覆蓋加權總分(見 `red-flags.md`)。例如無真實驗證 → 無論其他維度多高,總分封頂 40。

## 輸出格式

除了給人看的評分卡與白話結論,**務必在最後附一段結構化 JSON**,方便日後 `hvac-ai-paper-daily` 網站程式讀取,把「嚴謹度分數」融進現有「切題度分數」:

```json
{
  "paper": { "title": "...", "arxiv_id": "...", "peer_reviewed": false },
  "rigor_score": 75,
  "grade": "B",
  "dimensions": {
    "validation": 8.5,
    "baseline": 8.0,
    "internal_consistency": 8.0,
    "reproducibility": 5.0,
    "claims_vs_evidence": 8.5,
    "limitations_honesty": 9.0,
    "uncertainty": 5.0
  },
  "red_flags": ["preprint_not_peer_reviewed", "no_code_data", "modeled_not_deployed"],
  "one_liner": "誠實紮實的 preprint,但省電為模擬上限、程式未公開",
  "citation_advice": "引用時寫成『文獻模擬顯示潛力可達 X%』,勿寫成『已驗證省 X%』"
}
```

### 與網站現有分數的融合建議(給日後整合用)
`hvac-ai-paper-daily/api/papers.js` 目前的 `p.score`(0–100)是**切題度**。整合時建議**不要相乘覆蓋**,而是兩軸並存:
- `p.score` → 改標示為 `relevanceScore`(切題度)
- 新增 `p.rigorScore`(嚴謹度,來自本 skill 的 `rigor_score`)
- 前端可用二維呈現(切題 × 嚴謹),或給一個「總有料分 = 0.4×切題 + 0.6×嚴謹」的加權(權重可調)。
- 因為嚴謹度要讀全文、成本高,實務上只對切題度前段的論文才觸發本 skill 深評。
