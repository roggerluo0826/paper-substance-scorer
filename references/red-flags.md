# 紅旗清單與硬上限規則

紅旗分兩種:**扣分紅旗**(降低對應維度分)與**硬上限紅旗**(直接封頂總分,不管其他維度多高)。還有一類是**「必須向使用者點明的陷阱」**——不一定扣分,但不講出來會害使用者誤用。

## 硬上限紅旗(覆蓋加權總分)

| 紅旗 | 上限 | 為什麼 |
|---|---|---|
| 完全無真實數據驗證 | 40 | 沒驗證 = 一切結論懸空 |
| 對照組是稻草人 / 無 baseline | 55 | 改善幅度無意義 |
| 循環論證(拿模型驗證自己) | 45 | 邏輯上不成立 |
| 結果好到不真實且無法解釋來源 | 50 | 通常藏了假設或錯誤 |

## 扣分紅旗

| 紅旗 | 影響維度 | 說明 |
|---|---|---|
| 沒有 Limitations 章節 | 維度 6 → 0–2 | 沒有研究是完美的,不講 = 心虛/不誠實 |
| 沒有誤差棒 / 不確定性分析 | 維度 7 大扣 | 不敢面對數據變異 |
| 方法含糊、無法重現 | 維度 4 大扣 | 經不起檢驗 |
| 大量自我引用、期刊來路不明 | 維度 1、5 微扣 | 學術品質存疑 |
| 樣本極小卻宣稱普遍適用 | 維度 5 大扣 | 過度外推 |
| 系統性偏差未修正(如誤差全同號) | 維度 1 微扣 | 代表模型有一致性偏誤,非隨機 |

## 必須向使用者點明的陷阱(不一定扣分,但要講)

1. **preprint ≠ 同行評審**
   arXiv / 未正式發表的東西沒經過審稿。結論要明確標註「尚未同行評審,需自行嚴格檢驗」。並查它後來有沒有發表在正式期刊/會議。

2. **⭐ 模擬 vs 實測(最常見的誤導)**
   「省電 X%」「效能提升 Y%」——要看穿這是**模型/數字孿生算出來的潛力**,還是**真的部署到實體系統跑出來的績效**。前者只能寫成「模擬顯示潛力」,絕不能寫成「已驗證」。這是引用時最容易踩雷的地方。

3. **headline 數字建立在最弱模型元件上**
   檢查:貢獻最大宗省電/效益的那一塊,是不是正好來自論文自己承認「簡化、不精確」的模型?若是,headline 要降一格看待。

4. **驗證通過 ≠ 內部正確**
   輸出誤差指標(NMBE、CV(RMSE))過關,只代表「輸出像」,不保證「內部參數/機制對」。輸出準是必要條件,不是充分條件。要求分項驗證。

5. **作者利益 / 資金來源**
   若方法或產品由作者商業利益相關方資助,對正面結果要多一分保留(查 acknowledgements / funding)。

## 加分信號(反過來看,這些代表有料)

- 專節誠實列出多個具體 Limitations,甚至自曝核心弱點
- 主動提高驗證門檻(比標準更嚴)
- 誠實報告負面結果 / 失敗的假設
- 公開程式與數據(可重現)
- 分項驗證(逐子系統),而非只看整體
- 國家實驗室 / 中立機構背景 + 公開資助
